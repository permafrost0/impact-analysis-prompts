# 方針: 全フェーズ共通

全エージェントが作業の前に読みます。ここに書かれた方針は、エージェント定義の手順より**優先**されます。

- 方針は、振り返りの改善案をユーザーが採用したとき、または調査中にユーザーが「今後は」と決めたときに、オーケストレータが追記します。
- 1行に1つの方針を書き、末尾に `(POL-common-{連番} / {決定日} / {調査ID})` を付けます。
- 廃止した方針は消さずに、先頭に「【廃止 {日付}】」と理由を付けて残します。
- `docs/rules.md` に反する方針(ソースや設計書を変更させる、根拠を省かせる、点検を省かせる、など)は書きません。

## 方針(設計書の書き方)

追加開発の部分の見分け方など、設計書の書き方の決まりを書きます。ここに決まりがあれば、調査を始めるときに見分け方を毎回伝える必要がなくなり、シート名だけで足ります。

書き方の例(この例そのものは方針ではありません):
「設計書の赤字の行は、今回の追加・変更として扱う」「行全体の取り消し線は削除として扱う」「青字の行は、今回の対象外として扱う」
